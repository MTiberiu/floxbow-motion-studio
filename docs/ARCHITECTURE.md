# Architecture

The npm workspace separates host, player, renderer, SDK, animation library, audio, lyrics and project discovery. Node 22 runs orchestration using tsx. Electron main is intentionally a small CommonJS entry using Electron's native API; app/project/package code is TypeScript.

`npm run dev` starts two loopback servers then Electron. The shell origin has navigation and metadata only. The preview origin serves a repository-root Vite pipeline, so `/projects/<id>/<entry>` is a real transformed module URL. The selected module alone is dynamically requested; broken unselected compositions do not prevent shell startup. The manifest scanner returns per-project errors and requires the folder name to equal the unique ID. Missing entries, invalid paths, unsupported SDK versions and malformed JSON are reported. Realpath containment protects manifest/entry/timing/audio lookups against traversal and escaping symlinks.

Vite watches the project tree. A debounced event reloads the preview frame on add/change/delete, so new component dependencies and compile-error recovery are reliable. The shell polls manifests every 1.8 seconds. This deliberately resets playback rather than promising state-preserving fast refresh. Core shell editing still uses Vite HMR. No Electron rebuild is needed for scene edits.

Build uses a generated entry per project under `.studio/build/`, followed by independent Vite builds. Built projects use relative hashed asset URLs and a validated `dist/projects.json` catalog. Invalid projects retain error entries; build exits nonzero. `npm start` serves that snapshot on two loopback origins. New source projects require rebuilding in this mode.

The Remotion renderer CLI creates a temporary registerRoot entry, bundles only one project with Remotion's supported bundler, selects its composition and renders H.264 in headless Chrome. Rendering is never performed in the Electron renderer. The optional Python Whisper process similarly runs outside the UI. FFmpeg used by Remotion is managed by Remotion; the local Python worker needs FFmpeg on PATH.

Projects may also contain an optional `media.json` linked-media registry. Its public schema and Node resolver are exported from `@motion/project-loader/media`; the development shell mediates MP3/WAV, PNG and MP4 selection through a native picker and returns only asset names and availability to the UI. The Project Library shows a thumbnail from the first saved Timeline image clip when available. Inside a project, the Assets button opens the media panel; the project list stays out of the editor workspace. Images and Videos can be placed as independent Timeline clips by adding at the playhead or dragging onto Canvas or a visual Timeline track. The resolver's local file path must remain in a Node host process. A selected soundtrack is represented as a Timeline v1 Audio-track clip and is streamed into the Remotion preview and MP4 renderer by stable media ID. Video clips with embedded audio can create a separate `video-audio` clip that references the same MP4 asset and source in-point; the Video clip is muted so preview and render do not double the sound. In the live development editor, Music Analysis and the local Whisper adapter can read registered audio sources without exposing paths to the renderer; Music Analysis writes its own versioned report, while Whisper imports unverified subtitle clips. See [Project Media Registry](PROJECT_MEDIA.md), [Music Analysis](MUSIC_ANALYSIS.md) and [Lyrics Sync](LYRICS_SYNC.md).

## Security model

- Electron: sandbox, context isolation and webSecurity enabled; Node disabled. The small sandboxed preload exposes only typed window lifecycle and Timeline transport methods. Main validates sender window/role, fixed local route, project/session/window IDs, command sequence and exact payload shapes. Detached Timeline snapshots accept legacy v1 documents and current optional scene, Scene Moment, asset-group and clip scene-membership metadata while preserving strict nested-shape validation. Control messages remain capped at 4 KiB; validated Timeline snapshots and full-document edit commands have a separate 1 MiB cap. No raw ipcRenderer, filesystem access or generic command API is exposed. No remote navigation, popups or webviews; permissions denied.
- Project frame: separate origin, `sandbox="allow-scripts allow-same-origin"`, no top navigation, popup or download grants. Same-origin is needed for Vite modules, but the preview has a different port from the shell, so it cannot remove its parent sandbox or read shell state.
- CSP: only local origin scripts/media, inline styles, local HMR websocket. The shell permits `blob:` images and media so local Pose Studio files and browser-created media previews work without network access; it also permits media from the local preview origin. Project preview retains its documented blob image/media allowance. No external fetch, object embedding or nested frames. No remote fonts.
- Node: loopback-only HTTP listeners; project paths validated; no generic filesystem or command endpoint. Media registration accepts only a revision from the exact shell origin, gets a source path from a native picker, and returns no path to browser code.
- Important limits: loopback ports are not authentication. Vite exposes development source inside its allowed workspace. Project imports are not confined to their own folder by an OS policy. Infinite loops, resource exhaustion, browser exploits and malicious build-time imports are outside this boundary. Inspect external code; use a disposable OS account/container for hostile content. Production packaging, per-project worker processes and stronger resource isolation remain future work.

The file-system separation is an agent contract, not an adversarial sandbox. Tests cover ordinary compile/runtime exceptions, not arbitrary denial of service.

Electron allows one native child window for the registered Timeline panel. In desktop mode, Detach Timeline opens the controlled `TimelineView` in that fixed route; the primary editor replaces its Timeline with an Attach placeholder and keeps Canvas/Preview, Inspector, the sole `EditorSession`, and the sole preview iframe. Versioned snapshots flow from the primary renderer to the child; allow-listed, acknowledged commands return to the primary session. The main process validates and relays bounded messages but owns no project document or save path. Attach, native close, project changes, stale-command rejection, and recoverable sync errors return control to the primary editor. The browser-only workspace has no native detachment.
